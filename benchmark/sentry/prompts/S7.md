We're seeing orphaned flusher processes after the span consumer shuts down. The main process exits cleanly, but `ps aux` shows child flusher processes still running and consuming resources.

Expected behavior: when the span consumer's processing strategy shuts down, all flusher child processes should be terminated.

Actual behavior: the shutdown code only handles the single-process case. With the multi-process flusher refactor, there are now multiple flusher processes tracked in a dictionary, but the shutdown logic doesn't iterate over all of them to terminate each one.

This causes resource leaks — the orphaned processes hold Redis connections and keep polling for work indefinitely.

Please find and fix the shutdown code so all flusher processes are properly terminated.
