We have a subtle bug in our integration sync system. The `AssignmentSource` dataclass that tracks when assignment operations are queued has a stale timestamp problem.

All assignment sources created after server startup share the exact same `queued` timestamp — the one from when the module was first loaded. This means:

1. Debugging sync issues is impossible because all timestamps are identical
2. Any logic that relies on the `queued` time to determine ordering or staleness is broken
3. The timestamp doesn't reflect when the assignment actually happened

The issue is in the assignment source creation code. The timestamp should be fresh for each instance, not frozen at import time.

Please find and fix the root cause.
