We're seeing silent data loss in our uptime monitoring pipeline. Messages that fail during the flush callback are being permanently lost — they're removed from the queue buffer even though the processing raised an exception.

The symptom: our uptime check results sporadically go missing. Monitoring shows messages entering the consumer but the downstream system never receives them. No error logs are generated for the lost messages — they just disappear.

This happens under load when the flush target (e.g. Kafka producer) occasionally fails. The consumer keeps running without any indication that data was dropped.

The issue is in the queue-based consumer processing code. Please find and fix the root cause.
