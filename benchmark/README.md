# Benchmark: Real Production Bugs

Tests AgentInSync's token-savings effect on real production bugs from open-source projects. The agent navigates an unfamiliar codebase (Python/Sentry) using only code reading — no test execution, no build, no REPL.

## Layout

```
benchmark/
  lib/common.sh          ← Shared: Claude runner, correctness checker, CSV recording
  update-csv.py          ← Helper for writing rows into results.csv
  sentry/
    bugs.json            ← Bug catalog: 10 bugs from 5 PRs (stores seed_issue_id per bug)
    setup.sh             ← Clone repo + extract patches from GitHub PRs
    seed.sh              ← Manually seed a solution into the KB (auto-generates from patch)
    auto-run.sh          ← Run one Sentry bug (sources ../lib/common.sh)
    run-all.sh           ← Run all Sentry bugs
    results.csv          ← Results (generated by setup.sh)
    empty-mcp.json       ← Disables MCP for Phase 1 baseline runs
    ais-inject/          ← AIS rules/skills injected into worktrees for Phase 3
    patches/             ← PR diffs extracted by setup.sh
    prompts/             ← One .md per bug (S1–S10)
    .repo/               ← Cloned Sentry repo (gitignored)
    runs/                ← Run artifacts: stream logs + result JSON (gitignored)
```

For each bug, the agent is run twice on a fresh worktree of the cloned Sentry repo: once without AIS (baseline), once with AIS injected. AIS is toggled by copying or removing a `.claude/` directory into the worktree. The agent reads code only — it never executes tests or builds.

## Quick Start

```bash
# 1. Clone Sentry repo and extract patches
./benchmark/sentry/setup.sh

# 2. Export credentials
export AIS_API_KEY=ask_prv_xxx
export AIS_HOST=https://example.com   # default

# 3. Seed solutions into the KB (auto-generated from patch + bugs.json)
./benchmark/sentry/seed.sh --all

# 4. Dry run a single bug to verify setup
./benchmark/sentry/auto-run.sh S3 --dry-run

# 5. Run a single bug
./benchmark/sentry/auto-run.sh S3

# 6. Run all bugs
./benchmark/sentry/run-all.sh
```

## Prerequisites

- `claude` CLI (Claude Code >= 1.x)
- `gh` CLI (authenticated via `gh auth login`) — only needed for `setup.sh`
- `git`, `jq`, `python3`, `curl`
- AgentInSync server running at `AIS_HOST` (default: `https://example.com`)
- `AIS_API_KEY` env var — required for seeding and KB cleanup

## 3-Phase Protocol

Each bug runs through three phases:

**Phase 1 — Fix without AIS** (always runs)
MCP disabled, no AIS rules/skills injected. Agent debugs the bug from scratch using only code reading. Records token cost as the baseline.

**Phase 2 — Submit** (run 1 only, skipped if `seed_issue_id` set in `bugs.json`)
Resumes the Phase 1 session with AIS enabled, asks the agent to submit the fix to the KB. Skipped if the fix was incorrect or if a solution was already pre-seeded via `seed.sh`.

**Phase 3 — Fix with AIS** (always runs)
Fresh worktree with AIS injected. Agent runs the same bug prompt, searches the KB, and finds (or doesn't find) the seeded solution. Records token cost for comparison.

**Token savings** = (Phase 1 tokens − Phase 3 tokens) / Phase 1 tokens

The benchmark aborts Phase 3 with an error if the agent never called `search_before_fixing` — this indicates AIS injection failed.

## seed.sh — Pre-seeding Solutions

When Phase 1 fails to produce a correct fix (common for hard bugs in an unfamiliar codebase), Phase 2 is skipped and the KB has no solution for Phase 3 to find. `seed.sh` solves this by manually seeding the correct solution before running the benchmark.

The solution is auto-generated from data already in the repo: the symptom from `prompts/`, the root cause from `bugs.json`, and the actual code fix from `patches/`.

```bash
# Seed one bug (solution auto-generated from patch + bugs.json)
./benchmark/sentry/seed.sh S1

# Seed all unseeded bugs at once
./benchmark/sentry/seed.sh --all

# Override the auto-generated solution with custom text
./benchmark/sentry/seed.sh S1 --solution "The fix wraps the ack call in try/except..."

# Show the current seed_issue_id for a bug
./benchmark/sentry/seed.sh S1 --show

# Remove seed_issue_id from bugs.json (does NOT delete the issue from the KB)
./benchmark/sentry/seed.sh S1 --clear
```

The `seed_issue_id` is saved in `bugs.json` under the bug entry. When `auto-run.sh` sees it, Phase 2 is skipped automatically. Phase 3 still runs the agent normally — the agent is not told the issue ID and must discover the solution via search.

## auto-run.sh — Single Bug

```bash
./benchmark/sentry/auto-run.sh <BUG_ID> [options]
```

| Option             | Description                                                                           |
| ------------------ | ------------------------------------------------------------------------------------- |
| `--runs N`         | Repeat the full cycle N times (1, 2, or 3; default: 1). Submit happens on run 1 only. |
| `--dry-run`        | Print all commands without executing Claude sessions                                  |
| `--keep-worktrees` | Do not remove git worktrees after each run (useful for debugging)                     |
| `--no-vote`        | Prevent the Phase 3 agent from voting on solutions (measures search-only behaviour)   |
| `--search-limit N` | Inject `limit=N` into the `search_before_fixing` call (default: MCP server default)   |

```bash
# Run S3 once (full cycle: Phase 1 + Phase 2 + Phase 3)
./benchmark/sentry/auto-run.sh S3

# Run S3 three times (Phase 2 submit only on run 1)
./benchmark/sentry/auto-run.sh S3 --runs 3

# Dry run to verify patch applies and prompt loads
./benchmark/sentry/auto-run.sh S3 --dry-run

# Keep worktrees after the run for manual inspection
./benchmark/sentry/auto-run.sh S3 --keep-worktrees

# Test how many results the agent needs before finding the solution
./benchmark/sentry/auto-run.sh S3 --search-limit 1
./benchmark/sentry/auto-run.sh S3 --search-limit 5
```

## run-all.sh — All Bugs

```bash
./benchmark/sentry/run-all.sh [options]
```

| Option              | Description                                       |
| ------------------- | ------------------------------------------------- |
| `--bugs "S1 S3 S8"` | Run only the specified bugs (space-separated)     |
| `--jobs N`          | Run N bugs in parallel (default: 1 / sequential)  |
| `--skip-done`       | Skip bugs that already have data in `results.csv` |
| `--runs N`          | Passed through to `auto-run.sh` for each bug      |
| `--dry-run`         | Passed through to `auto-run.sh`                   |
| `--no-vote`         | Passed through to `auto-run.sh`                   |
| `--search-limit N`  | Passed through to `auto-run.sh`                   |
| `--keep-worktrees`  | Passed through to `auto-run.sh`                   |

```bash
# Run all 10 bugs sequentially
./benchmark/sentry/run-all.sh

# Run 3 bugs in parallel
./benchmark/sentry/run-all.sh --jobs 3

# Run only specific bugs
./benchmark/sentry/run-all.sh --bugs "S1 S2 S8"

# Resume a partial run (skip bugs that already have results)
./benchmark/sentry/run-all.sh --skip-done

# Full 3-run cycle for all bugs in parallel
./benchmark/sentry/run-all.sh --runs 3 --jobs 3

# Dry run everything first
./benchmark/sentry/run-all.sh --dry-run
```

## setup.sh — First-Time Setup

```bash
./benchmark/sentry/setup.sh [options]
```

| Option         | Description                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------- |
| _(none)_       | Full setup: clone repo, fetch PR patches, validate, copy AIS inject files, generate `results.csv` |
| `--skip-clone` | Re-extract patches without re-cloning (faster if `.repo/` already exists)                         |
| `--clean`      | Remove generated files (patches, results.csv, runs/) and re-run. Keeps `.repo/`.                  |
| `--clean-all`  | Remove everything including `.repo/` and re-run                                                   |

## Typical Full Workflow

```bash
# First time
./benchmark/sentry/setup.sh
export AIS_API_KEY=ask_prv_xxx

# Seed the KB with correct solutions for all bugs
./benchmark/sentry/seed.sh --all

# Run all bugs (Phase 1 baseline + Phase 3 with AIS)
./benchmark/sentry/run-all.sh --runs 3

# Check results
cat benchmark/sentry/results.csv
```

## Adding More Projects

To add another OSS project (e.g., Grafana):

1. Create `benchmark/grafana/`
2. Write `bugs.json` with bug catalog (same schema as `sentry/bugs.json`)
3. Write `setup.sh` to clone repo and extract patches
4. Write `auto-run.sh` that sources `../lib/common.sh` and implements `disable_ais()`, `enable_ais()`, `make_worktree()`
5. Copy `seed.sh` and update `PATCHES_DIR` / prompt path if they differ
6. Write prompts in `prompts/`
